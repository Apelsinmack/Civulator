# Development Log — 2026-03-20

## Session Summary

Major session: 12 features implemented, first 8-player tournament launched.

### What We Did

**C++ Module (civulator_core)**
- Created pybind11 C++ module mirroring Breach's architecture
- Implemented hex A* pathfinding with terrain costs + cylindrical wrapping
- Zero-copy numpy interface

**Coordinate System Migration**
- Switched from offset even/odd rows to **axial (q, r)** everywhere
- Distance formula: `max(|dq|, |dr|, |dq + dr|)` — no branching
- All 6 neighbors are the same direction vectors for every tile

**State Encoding**
- 11x speedup via numpy vectorization + cached terrain layer (9.7s → 0.85s)
- Switched to EnhancedStateEncoder (25 channels) as default

**Config System**
- `config.toml` now drives all gameplay parameters (terrain costs, LoS levels, map gen, training hyperparams)

**Line of Sight**
- Obstacle/vantage level system (plains=0, hills=1 vantage, forest=1 obstacle, mountains=2 obstacle)
- Hex line drawing algorithm for LoS checks

**Unit Stacking (Civ6-style)**
- 4 slot types: military (k=0), civilian (k=1), siege support (k=2), great person (k=3)
- Each slot stacks with everything except itself
- Select network output: `[n * m * k]` with masking for empty slots

**Training Stability**
- Target network (frozen copy, synced every 100 steps)
- Epsilon decay (1.0 → 0.05 over 5000 episodes, configurable)
- Multi-city build agent fix (was only seeing first city)
- Move mask fix (was 8-directional grid, now axial hex)

**Scaling**
- 24x48 map with 8 players (up from 4x8 with 2 players)
- FullyConvNetwork — no FC layers, map-size independent
- Randomized starting locations each episode

**Raylib Viewer**
- `scripts/watch.py` — hex grid rendering, terrain colors, unit/city markers
- Pan/zoom controls, HUD with player stats

**Tournament Mode**
- 8 agents with different architectures:
  - Small (8,16), Medium (16,32), Large (32,64) conv channels
  - Aggressive vs Patient epsilon decay
  - Standard (0.001) vs Fast (0.003) learning rate
- Each agent has its own network and hyperparameters

### Memory Crash Analysis

**Root cause**: 8 separate DQN agents × replay buffers on a 25-channel 24x48 map.
Each state tensor ≈ 115 KB. With 8 agents × 10k buffer capacity = ~9 GB RAM.
The system ran out of memory around episode 35.

### Decisions Made

1. **Switch to shared weights (self-play)** for main training loop — one network, one replay buffer, all players update it. This is standard and 8x more memory-efficient.
2. **Tournament mode stays** as an experiment format — train different architectures *sequentially*, then pit them against each other. Not 8 agents training simultaneously.
3. **Replay buffer size** should be configurable and capped sensibly. Add periodic `gc.collect()` + `torch.cuda.empty_cache()`.

### Ideas Discussed (not yet implemented)

- **Save "winning weights"** — checkpoint at episodes where an agent won. These could represent strategies that beat weaker opponents (useful for beginner-level bots).
- **Staged training** — freeze combat weights, then train build/diplomacy on top.
- **PPO instead of DQN** — would eliminate replay buffer entirely, better for this domain long-term.
